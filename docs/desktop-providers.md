# 桌面版模型提供商

Windows 客户端在「设置 → 模型提供商」中统一管理官方服务、中转、本地服务和原有提供商配置。提供商采用带分隔线的平面列表，点击后在弹窗中编辑设置及模型，保存与取消固定在底部。「测试连接」与 API 密钥等配置使用统一的设置行。新建提供商使用 Vercel AI SDK，同一种协议可以添加多个提供商，各自保存地址、密钥、请求头与模型列表。网页版继续使用原有设置与服务端路由。

内置模型已按 2026-10-24 的官方资料清理并更新，审计范围、来源与缓存兼容策略见[内置模型审计](builtin-model-audit.md)。没有可靠静态预设的来源使用获取列表或手动添加模型。

## 配置

1. 点击「新建提供商」，选择 OpenAI、DeepSeek、Anthropic、Gemini、兼容中转或本地 Ollama，填写名称、API 基础地址及密钥。接口兼容类型与请求头在「高级设置」中调整。「其他提供商」保留原有专用接入方式。
2. 点击「获取模型列表」，或手动填写服务商提供的实际模型 ID。显示名称仅用于界面，不会发给 API。
3. 需要看图的模型，勾选「图片输入」。随机性、单次回复限制、推理强度等生成参数，点击模型行的「参数」按模型设置，详见下文。
4. 保存后，在聊天输入框旁的模型下拉框中选择对应提供商的模型，也可以在全局模型设置、压缩模型或面具中选择。下拉框显示模型名称与提供商来源；提供商配置统一从设置中的「模型提供商」进入。压缩模型支持「跟随当前模型」。
5. 在「测试连接」中选择已启用的模型，发送一次简短测试请求。测试不会写入聊天记录；获取模型列表成功不代表模型聊天可用。修改配置或测试模型后，测试结果会清除。

修改全局模型会同步更新勾选「使用全局配置」的会话；在聊天菜单中手动选择模型会取消该会话的全局跟随。保存与取消明确区分，离开有未保存修改的页面时会提示。

侧栏「面具」右侧的「搜索会话」可展开搜索框，按标题或聊天正文筛选；关闭或清空恢复全部会话。搜索期间不支持拖拽排序。「设置 → 删除所有聊天会话」确认后删除聊天记录与草稿并保留一个空白会话，设置、模型供应商与面具保留；「清除所有数据」仍会清除全部本地数据。

| 协议                    | 官方基础地址示例                                   | SDK 追加的聊天路径                      |
| ----------------------- | -------------------------------------------------- | --------------------------------------- |
| OpenAI Chat Completions | `https://api.openai.com/v1`                        | `/chat/completions`                     |
| OpenAI Responses        | `https://api.openai.com/v1`                        | `/responses`                            |
| Anthropic Messages      | `https://api.anthropic.com/v1`                     | `/messages`                             |
| Gemini                  | `https://generativelanguage.googleapis.com/v1beta` | `/models/{model}:streamGenerateContent` |

使用中转时，将基础地址替换为中转提供的地址，并保留其版本或路由前缀，例如 `https://example.com/anthropic/v1`。不要填写完整聊天接口路径。协议由中转实际支持的接口决定，与模型名称无关。模型列表接口为基础地址后的 `/models`，中转未提供该接口时可手动添加模型。

自定义请求头使用 JSON 对象，同名请求头会覆盖默认值，例如 `{"X-Route":"personal"}`。默认分别使用 Bearer、`x-api-key` 或 `x-goog-api-key` 鉴权；也支持不需要密钥的本地兼容服务。

## 模型选项与推理

新提供商的生成参数按模型保存在提供商中：点击模型行的「参数」，可设置随机性、核采样、话题新鲜度、频率惩罚度、单次回复限制与推理强度，并在下方填写模型专用选项。每项默认为「服务商默认」，不发送；勾选「自定义」后才发送设定值。同一模型的聊天、标题、历史摘要与测试连接都使用这些设置；设置页与面具中的同名滑块只作用于原有提供商。弹窗按协议隐藏不支持的参数，保存时也会移除切换协议后不再支持的值：

| 参数                    | OpenAI Chat Completions | OpenAI Responses             | Anthropic Messages               | Gemini          |
| ----------------------- | ----------------------- | ---------------------------- | -------------------------------- | --------------- |
| 随机性                  | 原样发送，0–2           | 0–2；已知推理模型由 SDK 移除 | 0–1；开启 thinking 时由 SDK 移除 | 0–2             |
| 核采样                  | 原样发送                | 同上                         | 与随机性同时设置时被忽略         | 支持            |
| 话题新鲜度 / 频率惩罚度 | 原样发送                | 不支持，不显示               | 不支持，不显示                   | Gemini 2.5 忽略 |

通用 Chat Completions 不按模型过滤参数，是否生效取决于中转与模型；设置后可用「测试连接」确认中转是否接受。

「推理强度」由 AI SDK 换算为各协议的参数：Chat Completions 的 `reasoning_effort`、Responses 的 `reasoning.effort`、Anthropic 的 thinking 与 effort、Gemini 的思考等级或预算。「服务商默认」不发送；模型专用选项中填写的同类设置优先。需要标题与摘要更省时，可在模型设置中指定参数较轻的压缩模型。

旧版本中，新提供商总会发送会话里的单次回复限制（默认 4000），勾选「发送温度等采样参数」的模型还会发送会话里的四个采样值。升级后该勾选项移除，所有模型默认不发送这些参数，需要时在模型的「参数」中重新设置。

API 返回的独立 reasoning/thinking 内容显示在回复的「思考过程」折叠区，并随聊天保存。后续请求只发送正文，不重放思考内容；推理签名与加密推理状态不在此版本中往返传递。

「模型专用选项」使用 AI SDK 对应 provider 的命名空间。OpenAI Responses 可填写 `{"openai":{"reasoningEffort":"high","reasoningSummary":"auto"}}`；Anthropic 可填写 `{"anthropic":{"thinking":{"type":"enabled","budgetTokens":1024}}}`。实际支持的选项取决于模型与中转。通用 Chat Completions 使用 `relay` 命名空间，其支持范围取决于 `@ai-sdk/openai-compatible`，不是任意请求体透传。

标题和历史摘要默认使用当前实例与模型；可在模型设置中单独指定压缩模型。新提供商携带的历史只受「附带历史消息数」限制，历史摘要也会包含全部未摘要的消息；原有提供商仍按会话中的单次回复限制估算并截断历史。停止生成会保留已收到的正文和思考内容。连接中断、HTTP 错误与不完整流会作为失败显示，不自动重试。

## 旧数据、备份与边界

- 原有服务商通过统一连接列表编辑，继续使用原请求方式，保留专用密钥与接口版本等字段。旧会话保留原有路由，手动选择新连接后才切换。首次升级会清理完全未修改、且没有会话、面具、默认模型或压缩模型引用的自动迁移副本；已使用或已修改的连接保留。
- 删除或停用连接时，会提示受影响的会话、面具及全局配置；引用保留并提示重新选择模型，不自动切换到其他连接。连接标识与显示名称分开保存，重命名不会改变会话路由。删除原有服务商连接会清除对应凭据；启停状态、名称与模型设置一并备份。
- 新连接、原有连接的管理设置、收藏和最近使用包含在现有备份与同步数据中。恢复旧格式备份时会迁移；同步按更新时间完整替换 provider 列表与原有连接管理设置。备份中含 API 密钥，请按原有备份方式妥善保管。
- 新实例支持文本、图片输入、流式输出及独立推理展示；暂不支持原生工具调用或 MCP。
- 已移除实时聊天、NextChat AI 推广、GitHub 图标按钮及发现菜单下的插件、Stable Diffusion、历史搜索。
- 静态桌面包不运行 Next.js 服务端或 stdio MCP。网页版的 MCP 实现保留。
- 应用标识与存储位置保持原值，上游自动更新已关闭，避免覆盖自定义版本。

## 本地构建

使用 Node.js 24+、Yarn 1、Rust/MSVC 与 Windows WebView2 构建环境：

```powershell
yarn install --frozen-lockfile
yarn typecheck
yarn test:ci --runInBand
yarn app:build --bundles nsis
```

安装包输出到 `src-tauri/target/release/bundle/nsis/`，可执行文件为 `src-tauri/target/release/nextchat.exe`。`yarn export` 可单独验证桌面静态页面构建。
